## 1. 最严重的问题（建议先看这两条）

### 1.1 闲鱼发布助手的「扫描表单 / 填写整张表单」一点就报错

**位置**：`闲鱼发布助手/content.js`（旧版第 186 行）

```js
function scanForm(){const scan=scan();renderReport(scan);...}
```

**原因**：局部变量 `scan` 与函数 `scan` 同名。`const scan = scan()` 里右侧的 `scan` 会先按局部变量查找，
此时 `scan` 还在「暂时性死区」，抛出 `ReferenceError: Cannot access 'scan' before initialization`。
所以：

- 点「扫描表单」→ 直接报错；
- 点「填写整张表单」→ 前面填的内容其实写进去了，但最后一步调用 `scanForm()` 抛错，被 catch 成「填写中断」，让人误以为整张表都没填。

**修复**：改成 `const items = scan();`；`scanForm()` 现在返回识别结果，状态栏显示「检测到 N/17 个字段」。

**验证**：`tests/test_publisher.mjs` 里专门有一条 `扫描表单不再崩溃` 的回归测试，旧代码在这条测试上会直接抛错。

### 1.2 按一次 Alt+M 会采集两次

**位置**：`3D模型一键采集扩展/content.js` + `manifest.json` 的 `commands`

**原因**：快捷键有两条通路同时生效：

1. 页面里 `content.js` 监听了 `keydown`，检测 `Alt+M`；
2. `manifest.json` 又注册了 `chrome.commands` 的 `Alt+M`，background 收到后再给页面发 `MW_COLLECT`。

浏览器扩展的快捷键**不会拦截页面自身的 keydown**，所以一次按键触发两次采集：
两个时间文件夹、两套图片、两遍下载，容易把下载目录塞满，也不便于整理。

**修复**：`collectModel()` 增加「进行中」标志 + 1.5 秒冷却（`COLLECT_COOLDOWN_MS`），同一瞬间的两条触发只执行一次。
两条触发方式都保留（如果扩展快捷键被别的软件占用，页面快捷键仍然可用）。

**验证**：`tests/test_collector.mjs` 的最后一条测试同时调用两次采集，断言只保存一次。

## 2. 采集扩展（MakerWorld）

### 2.1 图片重复：同一张图下载了 w_1200 / w_1000 / w_400 三个版本

**现象**：一次采集保存 10 张图，但实际只有 6~8 张不同画面。旧代码只按「URL 字符串」去重，
而 MakerWorld 同一张设计图会给多个分辨率变体：

```text
.../design/ebda2a779a82de10.png?x-oss-process=image/resize,w_1200/...
.../design/ebda2a779a82de10.png?x-oss-process=image/resize,w_1000/format,webp/...
.../design/ebda2a779a82de10.png?x-oss-process=image%2Fresize%2Cw_400...
```

**修复**：

- 用「域名 + 路径（去掉扩展名）」作为图片 key，同一张设计图只保留一张；
- 同一 key 下按 `w_数字`、是否 webp、扩展名打分，优先 `w_1200` 原图；
- 用 `og:image` 里的模型目录（如 `CNa1de29ad059f9` / `DSM00000002530545`）过滤掉「相关模型」的图片和头像；
- 仍然最多 10 张。

**效果**（用你现有的采集数据回放，按「域名 + 路径去扩展名」这个 key 统计）：

| 样例 | 原始 JSON | 去重后 |
| --- | --- | --- |
| `model_2479285` | 10 张（4 张重复） | 6 张 |
| `model_2530545` | 10 张（3 张重复） | 7 张 |
| `model_2739633` | 15 张（7 张重复） | 8 张 |

### 2.2 打印时长把模型 ID / URL 里的数字识别成「xxx h」

**现象**：`guessed_print_times` 里出现 `"494293576\nh"`、`"2479285\nh"`、`"703h"` 这种垃圾值。

**原因**：旧正则 `\d+\s*(?:h|...)` 中的 `\s*` 会跨行，把上一行的长数字和下一行的 `h` 拼在一起；
也没有数值范围校验。

**修复**：

- 只允许空格/制表符，不再跨行；
- 只接受 `0.2 ~ 500 小时`（143.9 h 这种超大件仍然保留）；
- `3M`、`0.16mm` 这类不会再被当成时长/分钟。

**效果**：旧数据回放从 14 条（大半是垃圾）变成 `143.9 h / 7.7 h / 3.5 h` 三条有效值。
`extract_model_info.py` 也同步做了过滤，历史 JSON 重新提取也不会再出现垃圾时长。

### 2.3 标题带 `<platform>` 后缀，直接污染闲鱼标题

**现象**：采集 JSON 的 `title` 常是
`链锯人电次：释放终极链锯人Q版 - 免费 3D 打印模型 - MakerWorld`，
发布助手读进去后，闲鱼标题前 30 字就被平台后缀占满。

**修复**：采集时就清洗（`cleanTitle`），发布助手读取草稿时再清洗一次（双保险），另外解码 `&amp;` 等 HTML 实体。

### 2.4 其他采集扩展修复

| 问题 | 修复 |
| --- | --- |
| 采集完成后提示只显示「已保存」，看不到失败项 | 提示改为：耗材 / 时长 / 图片 N/N / 截图 / 失败项数量，可点击关闭 |
| 按钮保存失败时只说“保存失败” | 区分 JSON/截图/图片失败，并把错误回传 |
| 截图在图片下载之后才截，页面状态可能已变 | 改为先截图，再存 JSON，最后下载图片 |
| 同一时间连点采集会并发写两遍 | background 增加 `saving` 互斥，正在保存时直接返回 |
| `collector_version` 写着 `0.8.3-bulk-5images`，和 manifest 的 0.8.5 不一致 | 统一为 `0.9.0` |
| `Alt+M` 在中文输入法/非英文键盘下可能取不到 `m` | 增加 `event.code === 'KeyM'` 兜底 |
| 页面源码兜底抓图时会把 `data:`/`blob:` 也抓进来 | 统一走 `normalizeUrl()`，只保留 http(s) |
| 属性扫描把 `src/href` 全塞进文本，噪声大 | 只扫 `title/aria-label/alt/...`，图片单独走图片收集逻辑 |
| 许可证行重复两遍 | `uniq()` 去重 |

新增字段：`published_at`、`print_configs`、`file_links`（页面里如果有 3MF/STL/ZIP 直链会记录），
方便后续做「下载链接」相关功能。

## 3. 闲鱼发布助手

### 3.1 表单字段扫描的稳定性

- **旧版**：`label()` 每找一个字段就把全页 `label/span/div/p` 扫一遍，17 个字段 = 17 轮全页遍历，
  每次「填写整张表单」还会扫两遍，页面越大越卡。
- **新版**：一次扫描建立「文字 → 元素」索引和可见控件列表，17 个字段复用同一份索引；5 秒内复用缓存。
- **下拉选项**：旧版在整页里找「文字完全等于目标值」的节点，可能点到页面别处同名的文字。
  新版优先只在**已展开的下拉层**里找，并排除「大容器（宽 > 92% 屏宽、高 > 320px、子元素 > 15 个）」。

### 3.2 图片上传可能选错 input

旧版取页面上第一个 `input[type=file]`，闲鱼发布页可能有头像/视频等多个文件框。
新版按 `accept` 是否包含 `image`、是否 `multiple`、附近是否有「图片/照片/主图」文案打分，选最像商品图的那个。

### 3.3 草稿读取更聪明

- 优先读提取脚本输出的 `xianyu_title_safe` / `xianyu_copy_safe`（如果读的是 `.extracted.json`）；
- 读原始采集 JSON 时，自动清洗平台标题后缀、HTML 实体、`免费下载由…` 前缀、`为我助力` 推广段；
- 把 `need_manual_fields`（耗材克数、图片授权、商业授权）显示在「人工确认」提示里。

### 3.4 按钮职责分开

- 草稿页「填入闲鱼」= 只填**标题 / 描述 / 价格 / 原价**；
- 表单页「填写整张表单」= 分类 + 上面这些 + 成色 + 发货 + 图片。

（旧版两个按钮其实是同一个函数，草稿页点一下会把整个表单都动一遍。）

### 3.5 版本号与模型名

- 面板版本号改为从 `manifest.json` 动态读取（旧版面板写死 `v0.5`，而 manifest 是 `0.7.1`，`XY7_PING` 又返回 `0.7.0`）；
- 模型名改为 `deepseek-flash`（见第 7 节）。

### 3.6 其他

| 问题 | 修复 |
| --- | --- |
| 智能模式下本地服务返回「Key 无效」也会再直连一次，等于同一个错误请求花两份钱 | 只有「连不上本地服务/超时」才回落直连 |
| 本地服务模式没填 Key 时插件直接拦住，但服务端可能配了环境变量 | 本地/智能模式允许空 Key，由服务端决定 |
| 本地服务端最多等 DeepSeek 65 秒，插件却 60 秒就超时 → 被误判成「连不上」又去直连 | 服务端每次 30 秒、最多重试一次；插件本地请求超时 75 秒，直连仍 60 秒 |
| 连点扩展图标时 `toggle()` 并发进入，可能挂出两个面板 | 加 `state.mounting` 互斥 |
| 闲鱼如果用的是原生 `<select>`，模拟点击下拉选不中 | 原生 select 直接改 value + 派发 input/change；非原生仍走下拉模拟 |
| 每次点击扩展都 `insertCSS` 一次，样式重复叠加 | 先 `removeCSS` 再 `insertCSS` |
| `panel.css` 末尾 `.xy3d-rule-editor` 重复定义两遍 | 合并 |
| 直连请求没有 JSON 模式，偶发返回 Markdown 导致解析失败 | 加 `response_format: json_object`，并对空内容/坏格式重试一次 |
| 请求体 temperature 实际不生效（DeepSeek 思考模式默认开启，思考模式下 temperature 被忽略） | 关闭思考模式，temperature/速度才生效 |

## 4. 本地 AI 服务（`local_ai_server.py`）

### 4.1 SYSTEM_PROMPT 里的中文标点变成了 `?`（乱码）

旧文件里提示词是这样的：

```text
你是闲鱼3D打印商品文案编辑器?
只处理用户提供的资料?不虚构材质?尺寸?库存?...
```

本该是「，」「。」的位置全是 `?`。这会让模型读到一个语义怪异的提示词，直接影响输出质量。
**修复**：按原意重写为规范中文提示词，并补上 JSON 输出示例。

### 4.2 任何网站都能偷偷调用你的本地服务

旧版 `Access-Control-Allow-Origin: *` 且不校验来源。虽然服务只监听 `127.0.0.1`，
但**你浏览器里打开的任意网页**都能向 `http://127.0.0.1:8765/polish` 发请求；
如果服务端配了 `DEEPSEEK_API_KEY` 环境变量，对方不填 Key 也能消耗你的额度。

**修复**：`/polish` 检查 `Origin` 头：

- `chrome-extension://…`（插件后台）、没有 Origin（本地脚本/curl）→ 放行；
- `http(s)://…`（网页）→ `403 forbidden origin`。

### 4.3 HTTP 细节

- 旧版 `OPTIONS` 返回 `204` 却带响应体（不符合 HTTP 规范），且 `HTTP/1.0` 无长连接；
  新版 `204` 不带体、启用 `HTTP/1.1`；
- 提前拒绝（403/404/500）时请求体未读，旧写法会让长连接错位（下一次请求变成 `501 Unsupported method`）。
  新版在这些分支上带 `Connection: close` 主动断开；
- 客户端超时先断开时，`send_json` 不再抛 `BrokenPipeError`；
- `/health` 增加 `has_env_key` 字段（只返回 true/false，不泄露 Key）。

### 4.4 空内容重试

DeepSeek 官方文档提示 JSON 模式**偶尔会返回空内容**，新版遇到空内容或解析失败会重试一次。

## 7. DeepSeek 模型与参数（外部事实核对）

核对来源：<https://api-docs.deepseek.com/quick_start/pricing>、<https://api-docs.deepseek.com/guides/thinking_mode>、<https://api-docs.deepseek.com/guides/json_mode>

1. 现在应使用模型名 **`deepseek-flash`**。旧名 `deepseek-v4-flash` 仍被接受，但对应模型已下线，
   请求会转到 `DeepSeek-V4.1-Flash-1017` 并按 Flash 价格计费——能用，但不再推荐。
   已把插件与本地服务都改为 `deepseek-flash`，面板上的「模型」显示也同步。
2. **思考模式默认开启，且思考模式下 `temperature` 会被忽略**。旧代码传了 `temperature: 0.55` 其实没生效。
   文案任务不需要长时间思考，新版统一传 `thinking: {"type": "disabled"}`：更快、更省 token，温度才真正生效。
3. 开启 JSON 模式：`response_format: {"type": "json_object"}`，并在提示词里保留「JSON」字样和示例，
   减少「返回 Markdown 导致解析失败」的概率。
